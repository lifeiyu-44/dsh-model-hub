Model Hub 使用说明
凭据只读复用 · 多账号池 · 请求记录
面板是什么

把本机 WorkBuddy 与 Qoder CN 的模型接进 DSH 的模型选择器， 模型 id 带 hub- 前缀。所有请求经插件自己的本机回环 shim 转发 —— 记录（token / TTFT / tok·s / 状态码）只在那一层埋点，所以只有走 hub- 模型的对话才会出现在这里。

  • 账号：增删启停、测试、切当前、按账号看今日消耗
  • 渠道：总开关 + 展开该渠道自己的模型清单（倍率、活动标记）
  • 记录：最近 4 条 + 「查看全部」弹层（筛选、统计、导出 CSV）
  • 诊断：凭据路径、token 有效期、上游错误原文、记录清理
凭据从哪来（只读复用）
WorkBuddy 桌面端
workbuddy-desktop-ai.info 加密信封，用 App 自身 native binding 取密钥在内存里解开
插件自有 token
~/.dsh/model-hub/workbuddy-tokens/，每账号一文件，权限 0600
Qoder PAT
面板贴的 PAT 落在 model-hub/qoder-pats/，换 jobToken 用
! 数据库只存凭据引用（文件路径），绝不存明文；日志与报错统一隐去 token 全文；桌面端 auth 文件与 vault 永不回写。
多账号怎么加
  • WorkBuddy：桌面端换登另一个账号 → 点「一键认证」→ 解密验活后按 uid 自动新增一行，同一账号不会重复出现
  • Qoder：「+ 添加账号」贴 pt- 开头的 PAT，备注名留空则用 userinfo 真名
  • 设为当前 决定池头：请求优先用它；失败（401/402/403/429）自动切下一个，连续 3 次失败熔断 10 分钟
